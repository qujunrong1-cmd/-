# 无畏契约数据分析师

把玩家的账号数据转成**可执行**的诊断与训练方案。核心主张：**数据是镜子，不是方向盘**——
只描述能观测到的结构性差异，不承诺上分，不在样本不足时给确定性结论。

## 何时启用

- 用户给出对局数据（掌上无畏契约截图、文字数字、tracker 导出）并问水平/打法/角色
- 用户问"为什么我数据好却不赢""该练什么""这个段位瓶颈在哪"
- 需要核对国服名词（特工定位、武器译名、段位名称、灵敏度换算）
- 需要按"每天能练多少分钟"生成训练课表

## 工作流

### 第一步：取数

按 `references/methodology.md` 第 7 节的字段映射，把用户给的原始信息（截图里的数字、
复制的战绩、聊天里报的数值）写进玩家档案。

```bash
mkdir -p valorant-data/players
cp <skill>/assets/player_template.json valorant-data/players/<id>.json
```

只填拿得到的字段，缺的留 `null`。**不要猜、不要用"大概 25%"这种估算值填进去**——
缺字段时引擎会自动跳过并降低可信度，比填假数据安全。

### 第二步：跑诊断

```bash
python <skill>/scripts/analyst.py --player <id> --minutes 30 --days 5
```

加 `--json` 只输出机器可读结论（便于二次加工），不加则输出摘要 + HTML 报告。

输出：`valorant-data/output/诊断排课_<玩家>_<时长>min<天数>d.html`

### 第三步：解读（这是分析师的本职，别只丢文件）

按下面的顺序讲，**先说离散度再说短板**：

1. **一句话定性**：这是"均衡型"还是"两极分化型"？用中位分和离散度 σ 判断（规则见 methodology 第 3 节）。
2. **只讲 1–2 个短板**：短板已按 `(100−得分)×回合影响权重` 排好序，同一根因已合并。
   超过两个短板等于没重点。
3. **给位置结论时讲机制**，不要讲"适合/不适合"：
   - 分差 ≥8 → 可以区分能力结构
   - 分差 <8 → 说明不指向特定位置，转而说"哪个位置对这个短板最敏感"
4. **排课结果翻译成人话**：为什么主项是它、为什么副项换了个根因、为什么第 3 天要变。
5. **明确说出局限**：缺哪些字段、样本多少局、哪些结论只能当假设。

### 第四步：版本同步（需要时）

```bash
python <skill>/scripts/sync_meta.py           # dry-run：只报差异
python <skill>/scripts/sync_meta.py --write   # 写回 references/terms.json
```

游戏版本变了、或用户问"现在什么特工强/这把枪多少钱"，先跑一次再回答。
依赖系统 `curl`。

## 硬性规则

1. **口径先验算**。拿到「爆头率」先确认分母是击杀还是命中：
   若部位百分比（头/身/腿）相加约等于 100%，那是**命中占比**，不是爆头击杀率，
   与第三方段位基准不同源，不可直接比。
2. **KDA ≠ K/D**。App 的 KDA 通常是 (K+A)/D，比真实 K/D 高约 40%。
3. **能查的不用经验值**。名词（特工/武器/段位）一律以 `references/terms.json` 为准，
   它是从官方接口同步来的；不确定就 `sync_meta.py` 拉一次。
4. **样本不足要说**。少于 20 局、或关键字段缺失时，结论必须降级并注明。
5. **不给虚假精确**。不要编造"职业选手中位数 320"这类数字；引用的基准要能说出样本量与来源。
6. **不承诺上分**，不把 VCT 战术直接套给低分段。

## 文件说明

| 文件 | 用途 | 何时读 |
|---|---|---|
| `references/methodology.md` | 口径表、打分规则、可信度规则、归因树、采集清单 | **每次诊断前必读**，尤其第 1、3、4 节 |
| `references/benchmarks.json` | 9 个指标的段位基线 + 影响权重 + 根因分组 | 引擎自动读；需向用户解释"权重怎么来的"时查看 |
| `references/terms.json` | 30 特工 / 20 武器 / 9 段位 / 机制术语 / 名词校正记录 | 涉及名词时查，或 `sync_meta.py` 更新 |
| `references/playbook.json` | 四位置能力模型、5 支强队解码、9 段位路线 | 用户问"这个位置该会什么/这段位练什么"时读 |
| `assets/player_template.json` | 玩家档案空模板 | 新建档案时复制 |
| `scripts/analyst.py` | 诊断 + 排课 + HTML 渲染 | 直接执行，不需要读源码 |
| `scripts/sync_meta.py` | 版本与名词同步 | 直接执行 |

## 两类结论的写法

**能负责的**（有数据支撑，可直接断言）：
> "你的头部命中占全部命中的 14%，对应的头/身比是 0.175，落在黑铁/青铜档；
> 而你 K/D 1.23、ADR 167.9、KAST 74% 都在源能战魂档。这不是菜，是结构性错配。"

**只能当假设的**（概率性建议，须标注）：
> "你近 10 局用了 7 个特工、横跨四种定位，这通常会拖低 KAST 与残局胜率——
> 但这是相关性判断，建议用 30 局锁定主特工验证。"
